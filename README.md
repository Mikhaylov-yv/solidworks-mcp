# solidworks-mcp

MCP-сервер, через который ИИ-агенты (Claude Code, Claude Desktop и любые другие MCP-клиенты)
работают **вместе с конструктором** в запущенном SOLIDWORKS через COM API.

Сделан под русскоязычную практику: русский интерфейс SOLIDWORKS, ГОСТ-шаблоны и форматы листов,
основная надпись по ГОСТ 2.104, обозначения и наименования в свойствах модели.
Проверен на SOLIDWORKS Premium 2025 SP5 (RUS), Windows 11.

Основной сценарий — как у большинства конструкторов: сначала 3D-модель (деталь/сборка),
потом чертёж, связанный с моделью (виды, размеры из модели, основная надпись из свойств).

## Чем отличается от других SolidWorks-MCP

Агент работает **в вашем открытом SOLIDWORKS, одновременно с вами**, а не в отдельном сеансе:

- **Не мешает.** Перед любым изменением сервер ждёт, пока вы закроете диалог, завершите команду
  с PropertyManager и выйдете из эскиза. Если вы заняты дольше 30 с — агент получает «SOLIDWORKS занят,
  пользователь работает», а не сбивает вас. Чтение модели доступно всегда.
- **Одно действие агента = один шаг «Отменить».** В списке отмены они подписаны «AI: …».
- **Общее выделение.** Агент видит, что вы выделили (грани, рёбра, элементы, компоненты, размеры,
  виды чертежа — с размерами в мм), и сам может подсветить вам объекты.
- **Ничего не сохраняет и не закрывает** без вашей просьбы.
- **Полный API** через `execute_python`: всё, чего нет среди инструментов, агент делает напрямую
  в стиле VBA-макросов (`model.FeatureManager.FeatureExtrusion3(...)`).

## Инструменты

| Инструмент | Назначение |
|---|---|
| `status` | версия, открытые документы, активный (тип, единицы, конфигурация, материал), чем занят пользователь, размер выделения |
| `start_solidworks` | запустить SOLIDWORKS, если не запущен |
| `documents` | list / new (ГОСТ-шаблоны по умолчанию) / open / activate / save / save_as / close |
| `feature_tree` | дерево построения: элементы, эскизы, погашение, ошибки; для сборки — дерево компонентов |
| `get_selection` / `select_for_user` | выделение пользователя ↔ агента |
| `dimensions` | размеры модели (мм/°, «для чертежа»), изменение значений с перестроением |
| `equations` | глобальные переменные и уравнения |
| `custom_properties` | свойства файла/конфигурации: Обозначение, Наименование, п_Разраб… |
| `mass_properties` | масса, объём, площадь, центр масс |
| `rebuild` | перестроить (Ctrl+B / Ctrl+Q) и вернуть ошибки элементов |
| `view` / `screenshot` | ориентация, вписать, стиль отображения; снимок **только окна** SOLIDWORKS |
| `export` | копия в STEP / IGES / Parasolid / STL / PDF / DXF / DWG / PNG… |
| `create_drawing` | чертёж по модели: ГОСТ-формат (рамка + основная надпись), стандартные виды (1-й угол), изометрия, масштаб, размеры модели |
| `drawing_info` | листы, форматы, масштабы, виды и их связь с моделью/конфигурацией |
| `add_drawing_view` | добавить вид модели на лист |
| `insert_model_annotations` | «Элементы модели»: размеры, примечания, допуски, шероховатость, резьбы… |
| `execute_python` | произвольный Python с полным API SOLIDWORKS |

Параметры инструментов — в **миллиметрах и градусах**. В `execute_python` API работает в метрах
и радианах, есть помощники `mm()`, `deg()`, `to_mm()`.

## Установка

Нужны Windows, установленный SOLIDWORKS (2025; другие версии — см. ниже), Python 3.11+,
[uv](https://docs.astral.sh/uv/).

```powershell
git clone https://github.com/Mikhaylov-yv/solidworks-mcp.git
cd solidworks-mcp
uv sync
```

**Claude Code:**

```powershell
claude mcp add solidworks -s user -- uv --directory C:\путь\к\solidworks-mcp run server.py
```

**Claude Desktop** (`claude_desktop_config.json`):

```json
{ "mcpServers": { "solidworks": {
    "command": "uv",
    "args": ["--directory", "C:\\путь\\к\\solidworks-mcp", "run", "server.py"]
} } }
```

Другие MCP-клиенты — любой stdio-клиент с той же командой.

**Проверка** на живом SOLIDWORKS (создаёт свои документы во временной папке, открытые не трогает,
в конце закрывает созданные):

```powershell
uv run python smoke_test.py
```

## Настройки (переменные окружения)

| Переменная | По умолчанию | |
|---|---|---|
| `SOLIDWORKS_MCP_PROGID` | `SldWorks.Application` | конкретная версия: `SldWorks.Application.33` |
| `SOLIDWORKS_MCP_TLB_VERSION` | новейшая зарегистрированная | версия библиотеки типов API: 33 = 2025, 34 = 2026… |
| `SOLIDWORKS_MCP_IDLE_TIMEOUT` | `30` | сколько секунд ждать, пока пользователь закончит команду |
| `SOLIDWORKS_MCP_WORK_DIR` | `%TEMP%\solidworks-mcp` | кеш индекса API, временные файлы |

## Другие версии SOLIDWORKS

Сервер берёт библиотеку типов API из реестра (новейшую установленную), поэтому должен работать
с 2022+. Проверено только на 2025. Если на вашей версии что-то не так — откройте issue с выводом
`status` и ошибкой.

## Как устроен доступ к API (`swcom.py`)

Объекты SOLIDWORKS не отдают информацию о типе (`GetTypeInfo` не работает), поэтому обычный
pywin32 не отличает метод без аргументов от свойства (`model.GetTitle()` → «str is not callable»)
и не умеет [out]-параметры. Обёртка `SW` берёт DISPID по имени во время выполнения, а сигнатуру
(метод/свойство, типы аргументов, выходные параметры) — из makepy-модуля `sldworks.tlb`
(индекс строится один раз и кешируется). Возвращаемые объекты тоже оборачиваются, поэтому код
пишется как в VBA; [out]-параметры возвращаются кортежем:

```python
feat = model.FirstFeature()
while feat:
    print(feat.Name, feat.GetTypeName2())
    feat = feat.GetNextFeature()

ok, errors, warnings = model.Extension.SaveAs3(path, 0, 1, None, None, 0, 0)
```

## Безопасность

`execute_python` выполняет произвольный код на вашем компьютере с правами вашего пользователя —
так же, как макрос VBA. Это сделано намеренно: без него агент ограничен набором инструментов.
Подключайте сервер только к тем ИИ-клиентам, которым доверяете, и следите за тем, что агент
собирается запускать.

## Известные особенности

- Имена в русской версии локализованы: плоскости «Спереди/Сверху/Справа», виды «*Спереди»,
  «*Изометрия»… Помощники `std_planes(model)` и `model_view_name(model, "iso")` ищут их по
  позиции, а не по имени, поэтому работают в любой локализации.
- Пути к файлам — только с `\` (сервер нормализует сам; с `/` SOLIDWORKS молча возвращает None).
- Если шаблоны по умолчанию в настройках не заданы, берутся `gost-part.prtdot`, `gost-assy.asmdot`,
  `gost-part drw.drwdot`; формат листа — `<формат> - gost_sh1_<land|port>.slddrt`.
- **Основная надпись ГОСТ** читает свойства **конфигурации** модели (`$PRPSHEET`), а не общие
  свойства файла: задавайте Обозначение/Наименование/п_Разраб… с `configuration="active"`.
- Чертёж можно создать только по **сохранённой** модели.
- У чертежа «активный эскиз» (эскиз листа) есть всегда — для чертежей проверка «редактируется эскиз» не делается.
- `IEquationMgr.Add3` на SW2025 возвращает −1; сервер использует `Add2`.
- Если окно SOLIDWORKS свёрнуто, скриншот недоступен.
